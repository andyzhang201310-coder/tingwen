# 说话人识别与身份管理产品规范

- 产品名称：听文 TingWen（暂定）
- 模块名称：说话人识别与身份管理
- 文档版本：1.1
- 状态：已审批
- 适用平台：Android、iOS

## 1. 产品目标

为会议、课堂、访谈等多人语音记录场景提供自动说话人区分能力。

系统能够：
1. 自动识别录音中不同的声音，并分配临时说话人编号。
2. 将每段转录文字关联到对应的说话人。
3. 支持本地与云端双引擎识别。
4. 允许用户确认、修改和合并说话人身份。
5. 在会议结束后按人员查看发言内容。
6. 根据人员发言生成个人观点、问题、建议、决策和待办总结。
7. 生成整场会议总结，涵盖议题、讨论内容、决策和待办事项。
8. 所有总结均能追溯到原始转录文字及录音时间位置。

核心原则：

**先区分声音，再确认身份，最后整理发言。**

自动识别的临时说话人编号不等于真实姓名。

## 2. 已确认的产品决策

### 2.1 识别方式

采用本地 + 云端双引擎架构。

- 本地引擎：支持离线说话人识别。
- 云端引擎：提供云端辅助识别和结果补充。
- 统一结果层：将不同引擎的识别结果转换为统一的数据结构。
- 调度策略：根据网络、设备性能、用户设置和任务状态分配识别任务。
- 结果处理：保留引擎来源、时间区间和识别状态。

本地与云端不应分别维护互不关联的说话人编号。

### 2.2 身份管理

采用每场会议独立确认身份的方式。

- 每场会议拥有独立的 Speaker ID。
- 会议内通过临时编号区分不同人员。
- 用户在会议中或会后确认真实姓名。
- 不默认建立跨会议声音身份关联。
- 不默认通过历史会议声音判断当前会议人员身份。
- 后续如果增加跨会议个人声音档案，必须作为独立功能重新设计并取得授权。

### 2.3 总结方式

会后同时提供两类总结：

1. 按人员总结：整理每位参会者的发言、观点、建议、问题、承诺及相关待办。
2. 整场会议总结：整理会议主题、议题、讨论过程、关键结论、决策和待办事项。

两类总结必须关联原始发言片段，不能凭空生成结论或负责人。

## 3. 功能范围

### 3.1 MVP 必须实现

- 自动说话人分离。
- 本地与云端双引擎接口。
- 自动生成 Speaker 1、Speaker 2 等临时身份。
- 转录文字与说话人关联。
- 说话人首次出现时间及发言时间记录。
- 录音结束后确认和修改说话人姓名。
- 合并被错误拆分的同一说话人。
- 修正错误归属的转录片段。
- 未知说话人标记。
- 按人员筛选和查看发言。
- 点击发言跳转到对应录音位置。
- 按人员生成个人总结。
- 生成整场会议总结。
- 总结内容能够追溯原始发言。
- 说话人识别失败时保留原始录音和转录内容。

### 3.2 后续版本

- 个人声音样本注册。
- 跨会议身份匹配。
- 多设备联合录音和发言人关联。
- 说话人识别质量分析。
- 组织成员和会议参与者管理。

上述功能不属于 MVP，且跨会议身份匹配不得默认启用。

## 4. 用户使用流程

### 4.1 会议开始

1. 用户创建会议并开始录音。
2. 系统启动音频采集和实时转录。
3. 本地和云端识别引擎根据调度策略处理音频。
4. 检测到不同声音时分配临时 Speaker ID。
5. 转录片段关联对应 Speaker ID。
6. 无法判断的内容标记为未知说话人。

### 4.2 会议进行中

实时转录界面显示：
- 发言人编号或已确认姓名。
- 发言时间。
- 转录文字。
- 识别状态。
- 未确认身份提示。

用户可以在录音过程中修正发言人归属，但不能因为识别或修正操作阻塞音频采集。

### 4.3 会议结束后

系统进入发言人确认页面。

每个临时说话人显示：
- 临时编号。
- 首次发言时间。
- 发言次数。
- 发言总时长（可用时）。
- 代表性发言片段。
- 身份确认状态。

用户可以：
- 输入真实姓名。
- 修改姓名。
- 标记为未知人员。
- 合并两个说话人。
- 将某段发言重新分配给其他说话人。
- 播放代表性音频辅助确认。

身份确认仅作用于当前会议。

### 4.4 会后总结页面

会议详情页提供：
- 全文
- 按人员
- AI 纪要
- 待办事项

按人员页面包括：
1. 发言概览。
2. 发言原文。
3. 主要观点。
4. 提出的问题。
5. 建议与方案。
6. 决策与承诺。
7. 个人待办。

整场会议总结包括：
1. 会议主题和概览。
2. 主要议题。
3. 讨论要点。
4. 不同人员的主要观点。
5. 已确认的会议决策。
6. 待解决问题。
7. 会议待办事项。

每条 AI 归纳结果必须能够定位到支持它的原始发言。

## 5. 身份管理规则

### 5.1 临时身份

每场会议独立生成临时说话人身份。

示例：
- Speaker 1
- Speaker 2
- Speaker 3

不同会议可以出现相同的临时编号，但其身份彼此独立。

### 5.2 身份确认

用户可以将临时身份绑定到：
- 姓名
- 可选备注
- 可选组织或部门信息

未确认的身份必须显示为未确认或未知。

### 5.3 身份合并

用户可以合并同一人员被错误拆分的多个说话人。

合并后：
- 原始转录文字必须保留。
- 原始音频位置必须保留。
- 所有关联片段更新到目标身份。
- 保存合并操作记录。
- 支持撤销。

### 5.4 发言归属修正

用户可以将一条或连续多条转录片段重新分配给其他说话人。

人工确认结果优先于后续自动识别结果，系统不得静默覆盖人工修正。

### 5.5 跨会议身份边界

MVP 不进行跨会议身份匹配。

- 每场会议独立创建 Speaker 记录。
- 不根据历史会议自动推断当前发言人姓名。
- 不默认保存跨会议声纹身份。
- 不默认建立长期个人声音档案。
- 后续增加跨会议身份能力时，必须单独取得授权并设计相应的隐私控制。

## 6. AI 总结规则

### 6.1 按人员总结

每位人员的总结包含：
- 发言概览
- 核心观点
- 问题与疑问
- 建议与解决方案
- 决策与承诺
- 个人相关待办

### 6.2 整场会议总结

整场会议总结包含：
- 会议主题
- 主要议题
- 讨论内容
- 参与者观点
- 已确认决策
- 尚未解决的问题
- 待办事项及负责人
- 截止时间（仅在原文明确时提取）

### 6.3 事实约束

AI 必须遵循：
1. 不能将建议错误描述为已通过的决策。
2. 不能将讨论内容直接认定为个人承诺。
3. 不能凭空推断任务负责人。
4. 不能凭空生成截止时间。
5. 不确定的归属必须标记为待确认。
6. 总结内容必须关联原始发言片段。
7. 原始发言与 AI 总结必须分开保存。
8. 人工编辑的原始转录不能被 AI 重新生成的内容覆盖。
9. 不得将未确认的 Speaker ID 直接显示为真实姓名。

### 6.4 待办事项

每条待办至少包括：
- 任务内容
- 负责人（允许为空）
- 截止时间（允许为空）
- 来源说话人
- 来源转录片段
- 关联会议
- 确认状态

无法确认负责人的任务应标记为待确认。

## 7. 界面要求

### 7.1 实时录音页面

显示：
- 录音计时。
- 当前发言人。
- 不同说话人的颜色标识。
- 实时转录文字。
- 未知说话人提示。
- 本地和云端引擎状态。
- 识别异常提示。

### 7.2 身份确认页面

支持：
- 修改姓名。
- 播放声音片段。
- 合并说话人。
- 修改身份。
- 标记未知。
- 保存确认结果。

### 7.3 会议详情页面

支持：
- 按人员查看发言。
- 查看整场会议总结。
- 查看个人总结。
- 查看原始转录。
- 查看待办和决策。
- 播放原始录音。
- 点击总结定位到原文。
- 导出会议总结和个人发言内容。

## 8. 异常处理

| 场景 | 处理方式 |
|---|---|
| 本地引擎不可用 | 根据设置使用云端引擎 |
| 云端网络中断 | 本地继续处理，云端任务排队 |
| 两个引擎结果不一致 | 保留来源，进入统一结果处理 |
| 无法识别说话人 | 标记未知，不丢弃文字 |
| 多人同时发言 | 允许重叠时间区间，标记低置信度或待校正 |
| 声音相似 | 不自动认定为同一人 |
| 同一人被拆分 | 提供人工合并 |
| 不同人被合并 | 支持拆分和重新分配 |
| 人工修改身份 | 人工结果优先 |
| AI 总结失败 | 原始转录及身份数据仍可查看 |

## 9. 隐私和权限

1. 录音前展示必要的录音和参与者告知提示。
2. 录音和声音样本应提供清晰的用途说明。
3. 声音样本、声纹特征和身份映射按敏感数据保护。
4. 默认不进行跨会议身份追踪。
5. 用户可以删除声音样本和身份关联。
6. 云端处理前明确数据传输范围和用户授权。
7. 提供本地处理模式，具体能力以设备实际支持为准。

## 10. MVP 验收标准

- [ ] 一段多人录音可以生成多个临时说话人。
- [ ] 本地和云端识别结果可以统一处理。
- [ ] 转录片段能够关联 Speaker ID。
- [ ] 每场会议拥有独立的说话人身份。
- [ ] 用户可以确认临时说话人姓名。
- [ ] 用户可以修改某段发言的归属。
- [ ] 用户可以合并被错误拆分的说话人。
- [ ] 用户可以将无法判断的发言标记为未知。
- [ ] 人工修改不会被自动识别覆盖。
- [ ] 会议详情可以按人员筛选发言。
- [ ] 点击发言可以跳转至录音对应时间。
- [ ] AI 可以按人员生成结构化总结。
- [ ] AI 可以生成整场会议总结。
- [ ] 总结内容能够追溯原始发言。
- [ ] 说话人识别失败不会导致录音丢失。
- [ ] 识别任务失败不会阻塞录音。
- [ ] 不会默认跨会议匹配身份。

识别准确率、人数上限、延迟及资源消耗指标，必须在技术验证阶段通过真实设备和会议样本确定。

## 11. 非目标

MVP 不承诺：
- 在所有环境下百分之百正确识别说话人。
- 仅凭一次录音准确知道所有人的真实姓名。
- 完美区分所有重叠发言。
- 自动识别现实世界中的具体个人身份。
- 默认跨会议追踪参与者。
- 通过 AI 总结替代原始录音和转录内容。
